## Diagnosis

Not pushed yet, and you're still sitting on the wrong branch (often `main`) with one or more commits that belong elsewhere.

## Fix

**If you haven't committed yet**, this is the easy version — just stash and move:

```bash
git stash
git switch correct-branch
git stash pop
```

**If you already committed**, create the correct branch right where you are — it carries the commit(s) with it — then roll the wrong branch back:

```bash
git branch correct-branch
git reset --hard HEAD~1   # repeat for each commit to remove
git switch correct-branch
```

`git branch correct-branch` creates the new branch pointing at your *current* commit, so nothing is lost. The `reset --hard` only moves the old branch's pointer backward; the commit still exists and is now reachable from `correct-branch`.

<Callout type="tip">
Only one commit to move and you'd rather not touch the original branch at all? Use `git cherry-pick <commit-hash>` on the target branch instead, then `git reset --hard HEAD~1` on the original.
</Callout>
