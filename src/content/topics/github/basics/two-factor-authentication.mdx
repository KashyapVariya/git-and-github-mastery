## Why it matters

A password alone is one secret standing between your account and anyone who guesses, phishes, or leaks it. Two-factor authentication (2FA) adds a second, separate proof — usually a time-based code from your phone — so a stolen password alone isn't enough to get in.

GitHub has steadily expanded requirements for 2FA across accounts that contribute code, because a compromised developer account is a way to slip malicious code into real projects. Turning it on isn't just good personal hygiene; increasingly, it's simply required.

## How it works

After entering your password, GitHub asks for a second factor. The most common setup:

1. Install an authenticator app (like Google Authenticator, Authy, or 1Password) on your phone.
2. In GitHub's security settings, scan the QR code it shows you — this links your account to the app.
3. From then on, logging in asks for a 6-digit code that refreshes every 30 seconds, generated by the app.

GitHub also supports hardware security keys (like a YubiKey) and SMS as alternatives, though an authenticator app is the recommended default — it doesn't depend on phone signal and isn't vulnerable to SIM-swapping attacks the way SMS is.

<Callout type="warning">
When you enable 2FA, GitHub gives you a set of recovery codes. Save them somewhere safe and offline (a password manager, not a random text file) — if you lose access to your authenticator app and have no recovery codes, regaining access to your account can be a slow, frustrating process.
</Callout>

## What 2FA doesn't replace

2FA protects your login, but it doesn't replace other security basics: a strong, unique password (ideally from a password manager), being cautious about phishing emails claiming to be from GitHub, and using SSH keys or a personal access token instead of your password for Git operations over the command line — GitHub stopped accepting plain passwords for that years ago anyway.

<Callout type="tip">
Turn on 2FA before you set up SSH keys or tokens, not after. Some organizations require 2FA before they'll let you interact with their repositories at all.
</Callout>

## Try it yourself

Open Settings → Password and authentication on GitHub, enable two-factor authentication with an authenticator app, and store your recovery codes in a password manager.
