## Why it matters

Open-source projects bring together strangers from anywhere in the world, often communicating only through text. A code of conduct makes the ground rules explicit instead of assumed — what's welcome, what isn't, and what happens if someone crosses the line.

## What it usually covers

Most codes of conduct, including the widely-adopted [Contributor Covenant](https://www.contributor-covenant.org), cover the same handful of things:

- Examples of behavior that helps create a positive environment (empathy, constructive feedback, accepting responsibility for mistakes)
- Examples of unacceptable behavior (harassment, personal attacks, publishing others' private information)
- Who to contact to report a violation, and how
- What consequences look like — a warning, a temporary ban, a permanent ban

## Where it lives

A file named `CODE_OF_CONDUCT.md` in the repository root. GitHub automatically detects it and links to it from the repository's "Community" tab and the new-issue page, right alongside the license and contributing guide.

<Callout type="tip">
GitHub lets you add a Contributor Covenant template directly when creating a repository — you don't need to write one from scratch.
</Callout>

## Why it isn't just decoration

A code of conduct only means something if maintainers actually enforce it. Projects that publish one but never act on reports lose trust fast, while projects that quietly and consistently enforce theirs tend to build healthier, longer-lasting communities.

<Callout type="golden">
As a contributor, read the code of conduct once, early. It tells you a lot about how a maintainer expects disagreements to be handled — useful context before your first difficult code review.
</Callout>

## Try it yourself

Open a well-known open-source project's repository on GitHub and check its "Community" tab (or look for `CODE_OF_CONDUCT.md`). Compare it to another project's — most follow the same template with small differences in tone.
