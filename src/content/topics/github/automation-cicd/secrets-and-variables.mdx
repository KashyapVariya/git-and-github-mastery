## Why it matters

A workflow that deploys your app needs credentials — an API token, a cloud key. You can't put those in the YAML file in plain text; anyone who can read the repository could read them too. Secrets solve this: encrypted values that workflows can use, but nobody can read back out.

## Secrets

Add one under **Settings → Secrets and variables → Actions → New repository secret**. Give it a name (by convention, `SCREAMING_SNAKE_CASE`) and a value. Reference it in a workflow like this:

```yaml
steps:
  - name: Deploy
    run: ./deploy.sh
    env:
      API_TOKEN: ${{ secrets.API_TOKEN }}
```

GitHub automatically masks the secret's value in logs — if a step accidentally prints it, you'll see `***` instead of the real value. Secrets are never exposed to workflows triggered by pull requests from forks, by default, which prevents a malicious fork from exfiltrating them.

## Variables

Not everything needs encryption — a target environment name, a feature flag, a build number format. **Variables** work the same way but store plain text, visible to anyone with read access to the workflow:

```yaml
steps:
  - run: echo "Deploying to ${{ vars.ENVIRONMENT_NAME }}"
```

<Callout type="golden">
The rule of thumb: if leaking the value in a log or a fork's PR would be a security problem, it's a secret. If it's just configuration, it's a variable.
</Callout>

## Scopes

Both secrets and variables can be set at three levels, narrowest wins:

- **Repository** — available to all workflows in that repo
- **Environment** — scoped to a specific deployment environment (like `production`), can require approval to access
- **Organization** — shared across many repositories, optionally restricted to specific ones

<Callout type="warning">
Secrets are for *values*, not for anything you'd want to inspect later — there's no way to view a secret's value again once saved, only overwrite or delete it.
</Callout>

## Try it yourself

Add a repository variable (not a secret) called `GREETING` with any text value, then echo it from a workflow step using `${{ vars.GREETING }}` to see it appear in the logs.
